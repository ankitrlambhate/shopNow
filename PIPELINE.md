# shopNow: End-to-End DevOps Pipeline (Jenkins + Docker + Terraform + Ansible + EKS + Prometheus/Grafana)

This adds the CI/CD, infrastructure and monitoring layers on top of the original shopNow MERN app
(`frontend`, `admin`, `backend`, MongoDB). **Start with `README.md`** (execution guide, including the one-command `run.sh`);
this file is the detailed reference for the Jenkins route. Jenkins (Hero Vired server) orchestrates everything.

## 1. Architecture

```
 git push ─▶ GitHub ─▶ Jenkins (Hero Vired)
                          ├─ infra-terraform ─▶ VPC, EKS, 3 ECR repos, EC2 tools host, add-ons (state: S3 + DynamoDB)
                          ├─ config-ansible  ─▶ Docker, kubectl, AWS CLI, helm, node_exporter on the tools host
                          ├─ app-cicd        ─▶ test ▶ build 3 images ▶ push ECR ▶ deploy to EKS ▶ smoke test
                          └─ monitoring-setup▶ Prometheus, Grafana, Alertmanager, rules, dashboard

 Internet ─▶ NLB ─▶ ingress-nginx ─┬─ /<prefix>        ─▶ frontend (nginx) ─ /api ─▶ backend-service:5000 ─▶ mongo-0.mongo:27017
                                   └─ /<prefix>-admin  ─▶ admin (nginx)    ─ /api ─▶ backend-service:5000
```

| Concern | Implementation |
|---|---|
| Load balancing | AWS NLB in front of ingress-nginx (path routing), ClusterIP services inside |
| Orchestration | EKS 1.35, managed node group (3 x t3.medium SPOT) in private subnets across 2 AZs |
| Scalability | HPA on backend (2-5), frontend (2-4), admin (1-3); PodDisruptionBudgets; topology spread |
| Persistence | MongoDB StatefulSet + 5Gi gp3 EBS volume |
| Secrets | Jenkins credentials ▶ `scripts/create-secrets.sh` ▶ Kubernetes Secrets (nothing in Git) |
| Monitoring | kube-prometheus-stack; backend `/metrics`; ingress-nginx metrics; Jenkins and tools-host scraped |

## 2. What was changed in the original shopNow code (and why)

| File | Change | Reason |
|---|---|---|
| `backend/server.js` | Added `/metrics` (prom-client), request counter and latency histogram, graceful SIGTERM, server only starts when run directly | Monitoring requirement; testability; clean rolling updates |
| `backend/package.json`, lockfile | Added `prom-client`, `npm test` script | Same |
| `backend/tests/api.test.js` | New unit tests (no MongoDB needed) | Sprint 6 testing |
| `backend/Dockerfile` | HEALTHCHECK now calls `/api/health` | `/health` does not exist in the API (it returned 404) |
| `admin/nginx/default.conf` | Added `location /api/` proxy to `backend-service` | The admin app calls `<PUBLIC_URL>/api/...`, which previously fell through to `index.html` |

The original README mentioned `kubernetes/`, `jenkins/` and `scripts/` folders (and Helm charts and ArgoCD) that were not in the repository. The folders are created here; Helm charts and ArgoCD are not part of the assignment and were dropped.


Manifests under `kubernetes/k8s-manifests` are templates (`${NAMESPACE}`, `${ECR_REGISTRY}`, `${ECR_NAMESPACE}`, `${IMAGE_TAG}`, `${APP_PATH_PREFIX}`);
`scripts/render-manifests.sh` fills them in. Do not apply them directly.

## 4. Setup, sprint by sprint

**Prerequisites:** AWS account and IAM user/role (EC2, VPC, EKS, ECR, IAM, S3, DynamoDB); an EC2 key pair; your fork of this repo on GitHub;
the Hero Vired Jenkins URL; and on the Jenkins agent: `docker aws kubectl helm terraform ansible python3` (`sudo jenkins/install-jenkins-ec2.sh --tools-only`).

### Sprint 1: Jenkins and credentials
Jenkins ▶ Manage Jenkins ▶ Credentials ▶ add:

| ID | Kind | Value |
|---|---|---|
| `aws-credentials` | AWS Credentials | access key / secret |
| `ec2-ssh-key` | SSH Username with private key | user `ubuntu`, your key pair's private key |
| `shopnow-mongo-app-password` | Secret text | alphanumeric password |
| `shopnow-mongo-root-password` | Secret text | alphanumeric password |

Add a GitHub webhook to `https://<jenkins-host>/github-webhook/` (the app job also polls every 5 minutes as a fallback).
Try the images locally first: `scripts/build-and-push.sh <registry>/<ns> <tag> <prefix>` or `docker build backend`.

### Sprint 2: Terraform
```bash
./scripts/bootstrap-tf-backend.sh ap-south-1       # prints the state bucket name (once)
```
Jenkins job **infra-terraform** ▶ script path `jenkins/Jenkinsfile.terraform`. Run `ACTION=plan`, then `apply`.
Set `ADMIN_CIDR` to your IP/32 **plus the Jenkins server IP/32** (Jenkins needs the EKS API). Creates ECR repos `shopnow/{frontend,backend,admin}`.

### Sprint 3: Ansible
Job **config-ansible** (exact name, Terraform triggers it) ▶ `jenkins/Jenkinsfile.ansible`. Configures the tools host and runs `verify.yml`.

### Sprint 4: Application CI/CD
Job **app-cicd** ▶ `jenkins/Jenkinsfile.app-cicd`. Stages: checkout, backend tests, build 3 images in parallel, optional Trivy scan, push to ECR,
install cluster add-ons (gp3 StorageClass + ingress-nginx), render manifests, deploy (secrets ▶ Mongo ▶ backend ▶ frontend/admin ▶ ingress), smoke test.
On failure the three deployments roll back (`kubectl rollout undo`). MongoDB's app user is created automatically by an init script, so the manual `mongosh createUser` step from the original README is no longer needed.

Parameters worth knowing: `APP_PATH_PREFIX` (replaces the README's "aryan"; apps are served at `/<prefix>` and `/<prefix>-admin`), `NAMESPACE` (default `shopnow-demo`), `ECR_NAMESPACE` (must match Terraform `ecr_namespace`).
If a different IAM identity than the one that ran Terraform runs Jenkins, grant it cluster access:
```bash
aws eks create-access-entry --cluster-name shopnow-dev-eks --principal-arn <arn>
aws eks associate-access-policy --cluster-name shopnow-dev-eks --principal-arn <arn> \
  --policy-arn arn:aws:eks::aws:cluster-access-policy/AmazonEKSClusterAdminPolicy --access-scope type=cluster
```

### Sprint 5: Monitoring
Job **monitoring-setup** ▶ `jenkins/Jenkinsfile.monitoring`. Provide `GRAFANA_ADMIN_PASSWORD`; set `JENKINS_HOST` (hostname only) to scrape Jenkins and route critical alerts to a Jenkins webhook job
(needs the *Prometheus metrics* plugin and, for the webhook, *Generic Webhook Trigger*). Grafana user `admin`; the shopNow dashboard loads automatically.
Alerts (`monitoring/alert-rules.yaml`): backend down / no targets / 5xx rate / p95 latency, crash loops, replica mismatch, HPA maxed out, ingress 5xx, Mongo not ready / volume full, node CPU/memory/disk, Jenkins down / job failing.
Failed deployments also hit the `post { failure }` block (uncomment `mail` or `slackSend`).

### Sprint 6: Full automation and tests
Job **full-pipeline** ▶ `jenkins/Jenkinsfile.full-pipeline` runs Terraform ▶ Ansible ▶ app ▶ monitoring. Tests:
backend `npm test`; `scripts/smoke-test.sh` (frontend, admin, API proxying, products, an order create/fetch/cancel flow, replica counts);
`scripts/infra-tests.sh <cluster>` (cluster, add-ons, workloads, monitoring, ECR); `ansible/playbooks/verify.yml`.

## 6. Cost optimisation (10%)
SPOT nodes (about 70% cheaper; use `ON_DEMAND` for production) · single NAT gateway · t3.medium nodes and a t3.micro tools host · ECR lifecycle policy (last 10 images per repo) ·
HPAs with low minimums · 7-day Prometheus retention and small gp3 volumes · Grafana as `ClusterIP` (no extra load balancer) via `GRAFANA_SERVICE_TYPE` ·
`scripts/teardown.sh` after every session · keep `cluster_version` in standard support (extended support is 6x the control-plane price). Fixed costs to mention in the viva: the EKS control plane (about $0.10/hour), the NAT gateway, and the NLB.

## 7. Troubleshooting

| Symptom | Fix |
|---|---|
| Backend `CrashLoopBackOff`, "MongoDB connection error" | Wait for `mongo-0` Ready; check `kubectl -n shopnow-demo logs sts/mongo` and that `backend-secret` exists. The API connects only at startup, so `kubectl rollout restart deploy/backend` after fixing Mongo |
| Mongo user missing after changing the password secret | The init script only runs on an empty volume: delete the PVC (`kubectl delete pvc mongo-data-mongo-0`) and the pod |
| Frontend loads but is blank / 404 on assets | `APP_PATH_PREFIX` differs between the image build and the ingress; rebuild with the same value |
| `PVC Pending` | EBS CSI add-on not ACTIVE (`aws eks describe-addon ...`), or `gp3` StorageClass missing |
| HPA shows `<unknown>` | metrics-server add-on not ACTIVE |
| Jenkins `Unauthorized` from kubectl | Add an EKS access entry (Sprint 4); add the Jenkins IP to `ADMIN_CIDR` |
| Ansible `UNREACHABLE` | Instance still booting, wrong key, or `ADMIN_CIDR` blocks Jenkins |
| `terraform destroy` hangs on the VPC | Run `scripts/teardown.sh` first (removes the load balancers and volumes Kubernetes created) |
| ECR `RepositoryNotFound` | `ECR_NAMESPACE` in the job must equal Terraform `ecr_namespace` (default `shopnow`) |

## 8. Known limitations
- The backend has no authentication (it is a learning project): the admin and API endpoints are open to anyone who can reach the ingress. Restrict access (for example an ingress allow-list) before using real data.
- MongoDB is a single replica with a 5Gi volume; fine for the assignment, not for production.
- Traffic is plain HTTP; add an ACM certificate and a domain for HTTPS.
- `ADMIN_CIDR` defaults to `0.0.0.0/0`: tighten it.
- The brief's trailing "Multi-Cloud with Terraform" paragraph was treated as a copy-paste leftover; everything here is AWS only.
